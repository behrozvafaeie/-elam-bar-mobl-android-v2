# اعلام بار مبل — معماری بازسازی مستقل

## هدف
ساخت یک برنامه بومی Android با Kotlin و Jetpack Compose؛ خروجی هدف APK است. این شاخه از نظر کدنویسی مستقل از برنامه قبلی توسعه می‌یابد و شاخه main تغییر نمی‌کند.

## قواعد غیرقابل‌مذاکره
- هیچ جدول، رکورد، Storage bucket، Auth user یا Edge Function در پروژه زنده Supabase بدون بررسی و مجوز جداگانه حذف/بازسازی نمی‌شود.
- هیچ service_role یا secret پیامک داخل APK قرار نمی‌گیرد.
- همه عملیات حساس از RPC/Edge Function امن و با RLS انجام می‌شوند.
- نقش و مجوز از داده قابل اعتماد سمت سرور خوانده می‌شود؛ هرگز به user_metadata برای تعیین دسترسی اعتماد نمی‌کنیم.
- تاریخ در UI شمسی و زمان رویدادها با منطقه زمانی Asia/Tehran نمایش داده می‌شود؛ timestamp سمت سرور مرجع است.
- هیچ صفحه‌ای صرفاً نمایشی تحویل نمی‌شود؛ قابلیت‌ها باید به backend متصل و آزمایش شوند.

## نقش‌ها
1. super_admin: کنترل کامل و تنها مرجع نهایی مجوزها.
2. admin / senior_admin: فقط محدوده دسترسی اعطاشده در پنل مدیر ارشد.
3. company: ثبت‌نام، تکمیل پروفایل و اعلام بار.
4. driver: ثبت‌نام، مدارک، انتخاب چند مقصد و مشاهده/درخواست بارهای متناسب.
مشتری عادی حساب یا مسیر ورود ندارد. حساب شرکت و راننده تا تأیید مدیر ارشد فعال عملیاتی نمی‌شود.

## ساختار پیشنهادی ماژول‌ها
- app: Application، MainActivity، navigation و theme
- core/designsystem: رنگ، تایپوگرافی فارسی، اجزای مشترک و RTL
- core/model: مدل‌های دامنه و انواع وضعیت
- core/network: پیکربندی Supabase، مدیریت خطا و اتصال امن
- core/auth: ورود OTP، نشست، بازیابی نشست و خروج
- core/common: زمان تهران، تبدیل ارقام فارسی/عربی و ابزارهای مشترک
- feature/onboarding: ثبت‌نام و تأیید پروفایل
- feature/admin: داشبورد، کاربران، مدیران، مجوزها، مدارک، گزارش فعالیت و تنظیمات
- feature/company: پروفایل شرکت، اعلام بار چندقلمی/چندمقصدی، ویرایش و لغو مجاز
- feature/driver: پروفایل، مدارک، خودرو، چند مقصد، سالن بار و درخواست/رد
- feature/loads: فهرست، جزئیات، وضعیت و تاریخچه بار
- feature/chat: اتاق عمومی و گفت‌وگوهای خصوصی، رسانه و مجوزها
- feature/notifications: اعلان درون‌برنامه‌ای و push
- feature/smswallet: کیف پول پیامک و سوابق، فقط پس از تطبیق APIهای موجود
- feature/calls: تماس صوتی/تصویری؛ فعال‌سازی پس از بررسی signaling و آزمون دستگاهی

## قواعد محصول قطعی ثبت‌شده
- مبدأ بار ثابت «تهران» است.
- چند مقصد برای راننده و چند مقصد/قلم برای اعلام بار پشتیبانی شود.
- اقلام اعلام بار: مبل، سرویس خواب، اثاث منزل، تی‌وی کنسول، ناهارخوری، مبل استیل، مبل کلاسیک.
- نوع خودرو: وانت مبلی، کامیونت مبلی، کامیون ۶ متری، کامیون دربستی کار، خاور مبلی پتو‌دار.
- نوع بارگیری: دربست، روباری، نیم‌بار.
- کرایه به ازای هر مقصد و تعداد هر قلم مستقل است.
- محدودیت پنج‌قلمی قدیمی نباید در تجربه جدید اعمال شود؛ قبل از استفاده از RPC باید رفتار نامحدود آن با تست سرور تأیید شود.
- شماره بارنامه و تاریخ بارنامه در فرم اعلام بار وجود ندارد.
- شرکت پس از انتشار فقط در محدوده مجاز backend می‌تواند بار را ویرایش/لغو کند.
- راننده تماس با شرکت را از مسیر مجاز داخل برنامه انجام می‌دهد.
- تاریخچه وضعیت و اعلان‌های متناسب با خودرو/مقصد لازم است.

## ارتباطات
- اتاق عمومی: شرکت‌ها و مدیران؛ راننده فقط در صورت مجوز مدیر ارشد و در حالت فقط‌خواندنی.
- گفت‌وگوی خصوصی شرکت↔مدیران، شرکت↔شرکت و راننده↔مدیران با کنترل دسترسی سمت سرور.
- متن، تصویر و ویس در اولویت؛ PDF با کنترل نوع/حجم فایل.
- تماس صوتی پس از تست signaling؛ تماس تصویری مرحله بعدی و مشروط به پایداری.
- کنترل mute، حذف/سنجاق پیام و اجازه رسانه در اختیار مدیر ارشد.

## امنیت و کیفیت
- RLS روی تمام جدول‌های قابل‌دسترسی از Data API.
- عملیات حساس فقط از RPC/Edge Function مجاز؛ بررسی مجوز در سرور و ثبت audit.
- Android Keystore برای نگهداری امن نشست، عدم ثبت token/OTP در log.
- محدودسازی درخواست OTP، CAPTCHA/ضدسوءاستفاده در لایه مناسب و تأیید شماره.
- اعتبارسنجی نوع/اندازه فایل و مسیر Storage در سرور.
- تست واحد مدل‌ها و قواعد، تست repository، تست نقش/مجوز و تست end-to-end روی emulator و گوشی واقعی.
- CI باید APK را بسازد، امضا/شناسه بسته را بررسی کند و artifact را فقط پس از موفقیت بارگذاری کند.

## مراحل تحویل
1. تطبیق کامل قرارداد API با Supabase زنده (در حال انجام؛ فقط خواندنی).
2. پیاده‌سازی اسکلت چندماژوله و پیکربندی build قابل تکرار.
3. پیاده‌سازی Auth و پروفایل با تست.
4. بارها و تخصیص راننده با تست همزمانی.
5. پنل مدیر و مجوزها با تست RLS.
6. چت/اعلان/رسانه و سپس تماس.
7. تست امنیت، build، نصب و اجرای واقعی؛ تحویل APK فقط پس از تأیید.
