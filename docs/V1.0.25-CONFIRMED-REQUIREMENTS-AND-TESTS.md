# نسخه 1.0.25 — قوانین تأییدشده و کارهای پیاده‌سازی

این نسخه روی شاخه مستقل `feature/confirmed-user-rules-v1-0-25` توسعه می‌شود. هیچ تغییری به شاخه اصلی merge نشده است.

## قوانین قطعی محصول
- نشست شرکت و راننده روی همان دستگاه پس از اولین ورود باقی بماند؛ با بستن برنامه یا راه‌اندازی مجدد گوشی از حساب خارج نشوند. نشست با حذف حساب یا لغو امنیتی توسط مدیر ارشد اصلی باطل شود. نشست توکن‌محور است و «برای همیشه» به معنی ماندگاری تا زمانی است که حساب معتبر باشد، نه بی‌اعتنایی به حذف حساب، مسدودسازی یا لغو امنیتی.
- حذف حساب اعضا فقط توسط مدیر ارشد اصلی انجام شود؛ حذف حساب توسط خود کاربر یا مدیران دیگر مجاز نیست.
- شرکت‌ها و مدیران بتوانند بدون سقف تعداد، بار اعلام کنند.
- نام و شماره شرکت در فهرست عمومی بارهای رانندگان نمایش داده نشود.
- فقط راننده‌ای که بار را با موفقیت گرفته، بتواند از RPC امن اطلاعات تماس همان شرکت را دریافت کند. سایر رانندگان هیچ دسترسی به شماره تماس نداشته باشند. با لغو انتساب، دسترسی تماس قطع شود.
- مخاطبین پنل راننده و پنل مدیر جدا باشند.
- استوری برای نقش‌های driver/company/admin، با آرشیو ۲۴ ساعته و نظرگذاری آزاد. حذف استوری و نظرات فقط توسط مدیر ارشد اصلی.
- حفظ داده‌ها و جداول فعلی Supabase؛ تغییرات فقط افزایشی و با RLS.

## وضعیت بررسی
- شاخه پایه نسخه 1.0.24 APK را با موفقیت build و امضا کرده است.
- تست خودکار شبیه‌ساز به دلیل ناپایداری سرویس‌های Android emulator در زمان نصب شکست خورده؛ پیام خطا `Can't find service: package` و exit code 20 بوده است. این خطا اثبات‌کننده crash برنامه نیست؛ آزمون دستگاه واقعی هنوز لازم است.
- بارهای قابل دریافت راننده در حال حاضر فقط فیلدهای بار را query می‌کنند و نام/شماره شرکت را نمی‌خوانند.
- سیاست RLS بارها، خواندن شرکت را به مالک شرکت/مدیر مجاز محدود می‌کند؛ برای تماس راننده یک RPC اختصاصی لازم است.
- نشست راننده و شرکت با ذخیره refresh token رمزنگاری‌شده و بازیابی/refresh دوره‌ای پیاده شده است. ورود مدیر در کد فعلی هنوز نشست را به همان شکل ذخیره نمی‌کند و باید تکمیل شود.
- در UI فعلی دکمه خروج عادی برای مدیر وجود دارد؛ با قانون جدید باید حذف شود و خروج اجباری فقط به‌عنوان بخشی از حذف حساب/ابطال نشست توسط مدیر ارشد اصلی باقی بماند.
- پنل راننده هنوز کارت بار گرفته‌شده و دکمه تماس شرطی ندارد؛ RPC تماس در این commit افزوده می‌شود، اما تا اتصال UI و آزمون دو حساب، قابلیت تماس را کامل‌شده تلقی نکنید.
- UI استوری در سورس Android هنوز نیازمند پیاده‌سازی است. این migration جدول نظرات و RLS پایه را اضافه می‌کند؛ UI استوری/نظرات هنوز جداگانه لازم است.

## آزمون‌های الزامی پیش از انتشار
1. ورود و بازیابی نشست شرکت، راننده و مدیر؛ حفظ نشست بعد از force-stop و reboot.
2. حذف حساب توسط مدیر ارشد اصلی و بی‌اعتبارشدن نشست‌های قبلی.
3. بررسی اینکه هیچ مسیر عادی UI اجازه sign-out یا حذف حساب شخصی نمی‌دهد.
4. ثبت بار بدون محدودیت تعداد و نمایش بدون نام/شماره شرکت.
5. راننده A بار را می‌گیرد و فقط A می‌تواند RPC تماس را صدا بزند؛ راننده B و کاربران دیگر با پاسخ 403/خطای مجوز مواجه شوند.
6. با لغو انتساب، دسترسی A نیز قطع شود.
7. استوری: انتشار، مشاهده عمومی، انقضای ۲۴ ساعته، آرشیو صاحب، درج نظر، و حذف فقط توسط مدیر ارشد اصلی.
8. چت و مخاطبین با دو حساب راننده/مدیر و دو شرکت آزمایش شوند.
9. build، امضای APK، نصب و اجرای واقعی روی گوشی Android.

## محدودیت
این سند و migration به‌تنهایی به معنی تکمیل UI، تأیید امنیت کل سامانه یا آماده‌بودن APK نهایی نیستند.
