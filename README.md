# اعلام بار مبل — Android

برنامه بومی Android با Kotlin و Jetpack Compose؛ خروجی موردنظر فقط APK است.

## وضعیت واقعی این شاخه

این شاخه در حال بازسازی و آزمایش است. APK آزمایشی ساخته شده، اما برنامه هنوز نسخه عملیاتی یا آماده انتشار نیست.

### مواردی که اکنون در کد وجود دارند
- صفحه ورود فارسی و راست‌چین
- انتخاب نقش راننده، شرکت باربری یا مدیر ارشد
- ورود راننده و شرکت با شماره موبایل یا نام کاربری و رمز عبور از Edge Function `username-auth-v2`
- بررسی نوع حساب و وضعیت پرونده راننده/شرکت
- ورود مدیر ارشد از Supabase Auth و بررسی نقش `super_admin` و وضعیت مسدودی در جدول `admin_users`
- نمایش یک صفحه اولیه برای هر نقش و امکان خروج از حساب

### مواردی که هنوز پیاده‌سازی نشده‌اند
- فرم ثبت‌نام کامل راننده و شرکت
- بازیابی رمز برای حساب‌های بدون ایمیل
- نگهداری امن و پایدار نشست و refresh token؛ نشست فعلاً فقط در حافظه صفحه است
- سالن واقعی بارها، فیلترها و جزئیات بار
- فرم ثبت بار چندمقصدی/چندقلمی و ویرایش یا لغو بار
- درخواست حمل راننده و انتخاب راننده توسط شرکت
- پروفایل کامل، آپلود عکس و مدارک
- عملیات واقعی پنل مدیر ارشد و مدیریت مجوزها
- چت عمومی و خصوصی، اعلان‌ها، کیف پول پیامک و تماس
- آزمون عملی ورود با حساب‌های آزمایشی و بررسی کامل RLS

دکمه‌های پنل فعلی صرفاً نمای اولیه هستند و هنوز عملیات واقعی انجام نمی‌دهند.

## احراز هویت فعلی
- تصمیم فعلی محصول: بدون پیامک و بدون OTP پیامکی.
- راننده و شرکت از مسیر `username-auth-v2` با رمز عبور وارد می‌شوند.
- مدیر ارشد از مسیر استاندارد Supabase Auth وارد می‌شود و نقش او در `admin_users` کنترل می‌شود.
- پیش از انتشار باید قرارداد ورود با حساب‌های واقعی/آزمایشی و سیاست‌های RLS کامل آزمایش شود.

## ساخت APK
گردش‌کار **Android APK** در GitHub Actions با هر push به شاخه `main` یا `rebuild/clean-android-v1` اجرا می‌شود. خروجی آزمایشی در Artifact با نام `elam-bar-mobl-debug-apk` قرار می‌گیرد.

مشخصات بسته:
- Application ID: `ir.elambar.mobl`
- نسخه فعلی: `1.0.9` (versionCode: `10`)
- حداقل Android: نسخه 8.0 (API 26)
- خروجی فعلی debug است و امضای انتشار نهایی ندارد.

## امنیت و حفاظت از داده‌ها
- هیچ migration یا تغییری در جداول و داده‌های Supabase برای این پوسته اعمال نشده است.
- کلید service_role یا secret سرور در APK قرار نمی‌گیرد.
- کلید publishable داخل کلاینت عمومی است و به‌تنهایی مجوز دسترسی ایجاد نمی‌کند؛ RLS و کنترل سمت سرور ضروری‌اند.
- شاخه `main` و سورس قبلی برای حفظ امکان بازگشت دست‌نخورده باقی مانده‌اند.
- این APK تا تکمیل آزمون ورود، نشست، نقش‌ها، RLS و عملیات اصلی برای استفاده عمومی آماده نیست.
