# اعلام بار مبل — Android

برنامه بومی Android با Kotlin و Jetpack Compose. خروجی موردنظر فقط APK اندروید است.

## وضعیت فعلی سورس

این مخزن یک نسخه در حال توسعه است، نه نسخه عملیاتی نهایی.

مواردی که در کد فعلی پیاده‌سازی اولیه دارند:
- رابط فارسی و راست‌چین و انتخاب نقش راننده، شرکت و مدیر ارشد
- فرم ثبت‌نام راننده و شرکت و ثبت پرونده از طریق Edge Function با نام `device-register`
- ورود مدیر ارشد از Supabase Auth و بررسی نقش `super_admin`
- نگهداری امن refresh token روی دستگاه با Android Keystore
- بارگذاری مدارک راننده و تصویر پروفایل
- فرم افزودن چند بار و ارسال گروهی از مبدأ تهران از طریق RPC با نام `publish_tehran_load_batch_v2`
- نمایش فهرست بارها و جست‌وجوی رانندگان از طریق RPC

## محدودیت‌های شناخته‌شده و کارهای باقی‌مانده

- ورود حساب‌های قبلی راننده و شرکت در رابط فعلی فعال نیست؛ مسیر ورود مجدد باید تکمیل شود.
- بخش‌های مدیریتی فعلاً عمدتاً نمایشی/فقط‌خواندنی هستند و عملیات تأیید، رد، تعلیق و مدیریت نقش‌ها باید با کنترل دسترسی سمت سرور تکمیل شوند.
- گفتگوی عمومی و خصوصی، اعلان‌های کامل و تماس درون‌برنامه‌ای هنوز تکمیل نشده‌اند.
- عملکرد واقعی برنامه به وجود Edge Functionها، RPCها، جدول‌ها، Storage و سیاست‌های RLS سازگار در پروژه Supabase وابسته است.
- پیش از استفاده عملیاتی، نام و ساختار تمام توابع و جدول‌های فراخوانی‌شده باید با پروژه Supabase موجود تطبیق داده و روی حساب‌های آزمایشی بررسی شود.

## ساخت APK

گردش‌کار **Android APK** در GitHub Actions با هر push به شاخه `main` یا با اجرای دستی فعال می‌شود. خروجی آزمایشی با نام `elam-bar-mobl-debug-apk` در بخش Artifacts قرار می‌گیرد.

مشخصات بسته:
- Application ID: `ir.elambar.mobl`
- نسخه این ساخت: `1.0.12` (versionCode: `13`) — شاخه آزمایشی ۲۲۸
- حداقل Android: نسخه 7.0 (API 24)

## امنیت

- کلید `service_role`، رمز عبور یا کلید خصوصی را هرگز در سورس یا APK قرار ندهید.
- کلید publishable فقط برای شناسایی پروژه است؛ مجوز دسترسی را سیاست‌های RLS و توابع امن سمت سرور تعیین می‌کنند.
- هیچ جدول یا داده‌ای در Supabase بدون بررسی و تأیید صریح حذف یا بازسازی نشود.
- APK آزمایشی تا پایان آزمون ورود، نقش‌ها، RLS و عملیات اصلی، برای انتشار عمومی آماده نیست.
- در شاخه امنیتی ۲۲۸، ترافیک cleartext غیرفعال شده، پیکربندی اعتماد گواهی به CAهای سیستمی محدود شده و کنترل‌های پایه در GitHub Actions افزوده شده‌اند.
- جزئیات کنترل‌های لازم و مواردی که هنوز باید در Supabase آزمایش شوند در `SECURITY.md` ثبت شده‌اند.


## ورود کاربران در نسخه ۱.۰.۱۱
- ثبت‌نام جدید راننده و شرکت با شماره موبایل به‌عنوان شناسه ورود و رمز عبور انجام می‌شود.
- ورود کاربران موجودی که با همین روش ثبت‌نام شده‌اند با شماره موبایل و رمز عبور انجام می‌شود.
- نشست تازه‌شده در Android Keystore رمزنگاری و ذخیره می‌شود.
- بازیابی رمز برای حساب‌های شماره‌محور تا زمان فعال‌سازی پیامک، راهنمای پشتیبانی نشان می‌دهد؛ این نسخه ادعای تأیید پیامکی شماره را ندارد.
- حساب‌هایی که در نسخه‌های قبلی با ثبت‌نام بدون رمز ساخته شده‌اند، تا زمان مسیر مهاجرت/تأیید پیامکی ممکن است نتوانند با این روش وارد شوند.

## پیام‌رسان متنی — نسخه ۱.۰.۱۲
- اتاق عمومی شرکت‌های باربری در پنل شرکت‌های تأییدشده و پنل مدیر ارشد نمایش داده می‌شود.
- ارسال پیام متنی از طریق Supabase REST و با اعمال RLS سمت سرور انجام می‌شود.
- رانندگان در رابط کاربری این اتاق را دریافت نمی‌کنند؛ امکان دسترسی فقط‌خواندنی راننده همچنان نیازمند اعطای مجوز از مدیر ارشد است.
- تصویر، ویس، تماس صوتی و تصویری و ابزارهای مدیریت پیام در مراحل بعدی تکمیل می‌شوند.
